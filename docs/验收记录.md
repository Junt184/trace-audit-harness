## 2026-10-30：上下文空间、原生手动压缩

在确认所有任务均已空闲后开始修改；dokuwiki 任务 `c6268e44-ea2f-4761-84a3-24e9626a682c` 已于 07:34:53 UTC 正常完成，本次没有停止或压缩它。部署重启前逐次重新检查全部任务状态，未中断正在执行的审计。

实现直接复用 Pi SDK 1.4.0：当前上下文使用 `AgentSession.getContextUsage()`；手动摘要调用 `AgentSession.compact()`；自动压缩沿用既有 `compaction.enabled=true` 和 SDK 默认策略。没有重写 Agent 循环。上下文用量、容量、百分比、剩余空间和自动压缩状态出现在各任务结果/轨迹顶部，累计输入/输出 token 继续独立展示。容量取自任务模型配置，不能据此自动证明供应商实际支持该窗口。

手动压缩使用互斥的 `compacting` 状态，服务端在操作开始前就占用当前会话；运行中的审计不能压缩，压缩中不能继续或重复压缩。压缩时显示取消按钮，失败/取消恢复原审计状态并记录原因。SDK 的 compact() 本身会先 abort，因此 Harness 不对运行中会话调用它。原始会话只追加摘要，已有发现、笔记、报告不变；手动压缩不会自动发起下一轮审计。
